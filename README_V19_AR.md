# TAAMEN V19 — الحسابات الموثّقة والجلسات السحابية

**حالة النسخة:** V19 Implementation Candidate مبنية على V18 Hotfix 01  
**نسخة التطبيق داخل `package.json`:** `2.0.0` كما هي  
**النشر:** لم يتم  
**قاعدة البيانات:** Migration 0003 و0004 موجودتان في الملفات، ولم تُطبّقا على D1 Preview بعد  
**Google والبريد:** غير مفعّلين حتى إعداد بيانات المزودين على بيئة Preview  
**مزامنة المباريات والأرشيف:** غير مفعّلة حتى V20  
**سياسة الخصوصية:** الإصدار `2.3` بتاريخ 5 نوفمبر 2026، وتشمل إفصاح الحسابات السحابية

## 1. تجربة الدخول الجديدة — Guest-first

عند أول دخول دون ملف محلي أو جلسة سحابية موثّقة:

1. يفتح التطبيق في وضع زائر مؤقت؛ لا يُنشأ حساب أو ملف مستخدم وهمي في IndexedDB أو D1.
2. بعد ظهور عنصر الصفحة الرئيسية الفعلي، تظهر نافذة ترحيب مستقلة بخيارين: **تعرّف على TAAMEN** أو **المتابعة كزائر**.
3. اختيار المتابعة كزائر يغلق الترحيب ويحفظ أن المستخدم أكمل هذه الخطوة. حالة الترحيب مستقلة عن اكتمال الجولة وحفظ موضع الجولة.
4. عندما يطلب المستخدم ميزة تحتاج ملفًا محليًا أو هوية سحابية، يمكنه فتح شاشة الحساب صراحةً.

شاشة المصادقة لا تعرض خيار «المتابعة كزائر». تحتوي فقط على خيارين:

- **ملف محلي:** إنشاء ملف على هذا المتصفح فقط، دون حساب إنترنت أو إثبات بريد. تُحفظ بياناته على الجهاز.
- **حساب سحابي:** إثبات البريد برمز OTP أحادي الاستخدام أو الدخول عبر Google بعد تهيئة المزوّد. الاسم والبريد يصبحان هوية الحساب على TAAMEN Cloud؛ البريد للعرض فقط بعد التحقق.

علامة الاستفهام بجانب كل خيار تشرح التخزين والصلاحيات. شاشة إنشاء الملف المحلي تحتوي زر رجوع إلى اختيارات الحساب، ولا تحتوي خيار الزائر. الزائر يبقى متاحًا من نافذة الترحيب المستقلة، ويمكن إعادة الجولة من الإعدادات.

قبل إرسال رمز البريد أو بدء Google، يجب تحديد موافقة صريحة على سياسة الحساب وشروطه. تُسجّل نسخة السياسة وتاريخ الموافقة في D1 بعد اكتمال التحقق. إنشاء حساب سحابي لا يرفع بيانات الملف المحلي تلقائيًا.

## 2. الصلاحيات حسب طريقة الدخول

| الصلاحية | زائر | ملف محلي | حساب سحابي |
|---|---|---|---|
| تصفح الموقع والملاعب | نعم | نعم | نعم |
| إنشاء المباريات وحفظها | لا | نعم، محليًا | نعم، محليًا على الجهاز |
| الأرشيف والتحليلات الشخصية | لا | نعم، محليًا | نعم، محليًا على الجهاز |
| استخدام TAAMEN AI | لا | نعم بعد موافقة AI المستقلة | نعم بعد موافقة AI المستقلة؛ المحادثة محلية |
| مسودات الملعب التكتيكي | معاينة فقط | نعم، محليًا | نعم، محليًا |
| مكتبة الخطط السحابية | لا | لا | نعم، بعد إثبات الحساب |
| مزامنة المباريات بين الأجهزة | لا | لا | غير مفعّلة حتى V20 |

الحساب السحابي لا يحوّل بيانات الجهاز إلى بيانات سحابية تلقائيًا. صلاحية حفظ خطة في مكتبة الخطط منفصلة عن صلاحية مزامنة المباريات والأرشيف.

## 3. تقسيم بيانات الملف

| البيانات | ملف محلي | حساب سحابي |
|---|---|---|
| الاسم الأول واسم العائلة | محليان | محفوظان في D1 ويظهران بالملف |
| البريد | اختياري ومحلي وغير موثّق | بريد الحساب الموثّق ويظهر للقراءة فقط |
| صورة الملف | محلية دائمًا | محلية دائمًا |
| الهاتف | محلي دائمًا | محلي دائمًا |
| تفضيلات الجهاز/اللغة/الحركة | محلية | محلية |
| الخطط التكتيكية | المسودات المحلية تبقى محلية؛ المكتبة السحابية تتطلب حسابًا | مكتبة الخطط الحالية مرتبطة بالحساب |
| المباريات/الأرشيف | محليان | لا مزامنة عامة قبل V20 |
| محادثات TAAMEN AI | محلية | محلية؛ لا يوجد Cloud Chat Storage |

عند تسجيل الدخول السحابي، يحافظ التطبيق على صورة المستخدم وهاتفه المحليين. الاسم السحابي في D1 هو المصدر المعتمد، وقد تُحفظ نسخة عرض محلية منه لدعم الواجهة دون اتصال، لكنها ليست إثبات هوية ولا تتقدم على D1. لا يُخزن البريد السحابي مجددًا داخل IndexedDB. تسجيل الخروج لا يحذف بيانات الجهاز المحلية.

## 4. كيف تعمل المزامنة؟

V18 جهّز بروتوكول Push/Pull مع Revision وCursor وIdempotency وTombstones. V19 يضيف إثبات الهوية وربط الحساب، لكنه لا يشغّل مزامنة المباريات.

- كل جهاز يحفظ محليًا أولًا.
- موافقة المستخدم الحالية تسجل تفضيله لإصدار سياسة المزامنة، ولا تُفعّل النقل.
- الخادم يفرض `cloud_sync_enabled = 0` في V19.
- قبل V20 سنعرض معاينة للبيانات التي يمكن نقلها، ونستبعد PRIVATE والصور والهاتف والمحادثات والإعدادات المحلية.
- V20 مسؤول عن أول ترحيل، وOutbox، وPull بين جهازين، وحل التعارضات والاستعادة.

## 5. اللغات وتجربة المنتج

- اللغات المعروضة بأسمائها الأصلية: العربية، English، Español، Français، Deutsch، Português، Türkçe.
- لا تستخدم قائمة اللغة أعلامًا أو رموز دول.
- شارة `BETA` تظهر على اللغات الخمس الإضافية فقط، بلون كهرماني هادئ.
- العربية RTL، وبقية اللغات LTR. اختيار اللغة يُحفظ في `localStorage` تحت `taamen-language` ويُطبق دون إعادة تحميل.
- الترحيب والجولة التفاعلية وتسميات التنقل وأسماء الأقسام وحالات TAAMEN AI مترجمة للغات السبع.
- **حد الترجمة:** محتوى صفحات المنتج القديمة، وبعض شاشات الحساب والنماذج والنصوص داخل الصفحات، ما زال يعتمد العربية/الإنجليزية. لذلك اللغات الخمس الإضافية BETA وليست ترجمة كاملة لكل الصفحة. هذا موضح للمستخدم في قائمة اللغة.

### الجولة التفاعلية

تنتقل الجولة عبر الصفحات الفعلية بالترتيب: Home، Tactical Board، Match Center، Archive، Stadiums، Analytics، Settings، ثم TAAMEN AI. تستخدم `data-tour` ثابتة، وتنتظر الصفحة والعنصر المستهدف بمهلة محدودة، وتتيح السابق والتالي والتخطي والإغلاق، وتستعيد موضع الجولة بعد إعادة التحميل. عند غياب هدف لا تعلق الواجهة؛ تتجاوزه وتوضح ذلك. بطاقة الجولة تتكيف مع الهواتف وتحترم `prefers-reduced-motion`.

### إعدادات المساعد

واجهة TAAMEN AI تتصل بمسار `/api/ai/quota` و`/api/ai/chat` الفعليين عبر Worker، مع CSRF وحدود الرسائل والسياق والحصة اليومية. حالات الواجهة تشمل الفحص، انتظار الموافقة، الحاجة لملف محلي، الجاهزية، نجاح الاتصال الفعلي، الخطأ، عدم التوفر والمهلة. لا يظهر `Connected` إلا بعد نجاح طلب حقيقي إلى النموذج. لم يُجرَ استدعاء حي للنموذج خلال هذه الحزمة.

## 7. إعداد مزودي تسجيل الدخول — Preview فقط


لا توجد بيانات Google أو قالب بريد تحقق داخل هذه الحزمة. أضف إعدادات جديدة لبيئة Preview فقط بعد نجاح الفحوصات المحلية:

- `AUTH_PEPPER` — Secret عشوائي قوي، 32 بايت على الأقل.
- `EMAILJS_SERVICE_ID` — معرّف خدمة EmailJS المسموح باستخدامها من Worker Preview.
- `EMAILJS_AUTH_TEMPLATE_ID` — معرّف قالب جديد مخصص لرمز التحقق؛ لا تعِد استخدام قالب الدعم أو الرد التلقائي.
- `EMAILJS_PUBLIC_KEY` — المفتاح العام المطلوب لطلب EmailJS من Worker.
- `GOOGLE_CLIENT_ID` — OAuth Client ID.
- `GOOGLE_CLIENT_SECRET` — Secret.
- `GOOGLE_REDIRECT_URI` — عنوان callback المسجل حرفيًا في Google OAuth، وينتهي بـ`/api/auth/google/callback`.
- `EMAILJS_PRIVATE_KEY` — اختياري عند الحاجة وفق إعداد EmailJS.
- `EMAILJS_ORIGIN` — أصل HTTPS لمضيف Preview المعزول، ويجب إضافته إلى Origins المسموح بها في EmailJS.

قالب EmailJS الجديد يجب أن يستقبل: `to_email`, `to_name`, `otp_code` (أو `verification_code`), `app_name`, و`expires_minutes`.

لا تضع أيًا من القيم السرية في `VITE_*` أو `wrangler.jsonc` أو Git. لا تنفّذ أوامر `wrangler secret put` قبل التأكد أن Wrangler يشير إلى إعداد Preview المقصود.

## 8. إعداد D1 Preview

**لا تطبّق أي Migration قبل نجاح فحوصات Windows والبناء.** قاعدة Preview الحالية لديها 0001 و0002 مطبقتان بالفعل. V19 تضيف Migration 0003، وHotfix ربط المزوّدين يضيف Migration 0004. بعد إعداد Worker Preview مستقل ومراجعة قاعدة Preview المقصودة، يجب أن تظهر 0003 و0004 فقط كترحيلات معلقة؛ لا تعِد 0001 أو 0002.

```powershell
npx wrangler d1 migrations list taamen-plans-preview --remote
```

تأكد أن المعلّق هو التالي وبالترتيب:

```text
0003_verified_cloud_accounts.sql
0004_account_provider_linking.sql
```

ثم طبّقهما مرة واحدة على Preview فقط:

```powershell
npx wrangler d1 migrations apply taamen-plans-preview --remote
npx wrangler d1 migrations list taamen-plans-preview --remote
```

تحقق من الجداول وفحص السلامة:

```powershell
npx wrangler d1 execute taamen-plans-preview --remote --command "SELECT name, type FROM sqlite_master WHERE type IN ('table','index') AND name NOT LIKE 'sqlite_%' ORDER BY type, name;"
npx wrangler d1 execute taamen-plans-preview --remote --command "PRAGMA quick_check;"
npx wrangler d1 execute taamen-plans-preview --remote --command "PRAGMA foreign_key_check;"
```

لا تعِد 0001 أو 0002. لا تنشئ Production D1. لا تضف Preview D1 إلى `env.production`. إعدادات الأسرار ممنوعة على إعداد Wrangler الحالي قبل عزل Preview؛ راجع `docs/setup/V19_PREVIEW_AUTH_CONFIGURATION_AR.md`.

## 9. الفحوصات وحدود التسليم

راجع `TAAMEN_V19_UX_CLOUD_HOTFIX_01_REPORT_AR.md` و`TAAMEN_V19_QA_REPORT.md` لنتائج Hotfix الحالية. الفحوصات المحلية تغطي Worker وBackend ومسارات ربط المزوّدين والجلسات وإزالة Acquisition. لا تُعتبر اختبارات OAuth أو EmailJS الحية مكتملة دون إعداد Preview المعزول ومفاتيح المزودين. كما لم تُختبر KV وAI عن بُعد ضمن هذا الإصدار.

تثبيت الاعتماديات في بيئة التسليم تعطل بسبب فشل الوصول إلى npm registry (`EAI_AGAIN`) وترك `node_modules` غير مكتمل؛ لذلك اختبارات الواجهة التي تحتاج React/Lucide قد لا تُحمّل، كما أن `typecheck` و`build:production` محجوبان إلى حين تثبيت الاعتماديات الصحيحة. انسخ `package-lock.json` الذي اختبرته على Windows بعد `npm audit fix` قبل `npm ci`، ولا تشغّل `npm audit fix` مجددًا بصورة عمياء.

**لا تنفّذ `wrangler deploy`. لا تغيّر إعدادات Production.**
