هذه هي النسخة الكاملة الحالية للمشروع، وليست Patch منفصلًا.

- **مرحلة المصدر:** V18.
- **رقم التطبيق:** `2.0.0` — لم يتغير.
- **الأساس:** دمج V17 الأصلية ثم Hotfix 01 ثم Hotfix 02 الخاص بربط D1 Preview، وبعدها تنفيذ V18 فوقها.
- **النشر:** لم يتم.
- **الحسابات السحابية:** لم تُفعّل؛ المصادقة تظل مغلقة حتى تنفيذ V19.

اقرأ [دليل V18 العربي](README_V18_AR.md)، ثم [المواصفات التقنية لمحرك المزامنة](docs/cloud/V18_SYNC_ENGINE_AR.md)، وتقرير [V18 QA](TAAMEN_V18_QA_REPORT.md).

## ما أضافته V18؟

تضيف V18 أساس مزامنة لبيانات نصية منظمة بصيغة JSON داخل D1، وليس تخزين ملفات أو صور:

- مزامنة الاسم الأول واسم العائلة فقط من الملف الشخصي.
- مزامنة سجلات المباريات والنتائج والأرشيف وإحصائيات المباراة والأداء الشخصي.
- مؤشر تغييرات `cursor` مختصر يحتفظ بآخر حالة لكل سجل بدل تاريخ تعديل كامل.
- منع الكتابة فوق تحديث أحدث عبر `revision` وCompare-and-Swap.
- منع تكرار العملية عبر `idempotency`.
- حذف منطقي `tombstones` لا يحتفظ بمحتوى المباراة بعد الحذف.
- واجهات Worker محدودة الحجم والحقول والطلبات.
- عميل TypeScript ومخزن Outbox محلي يستعملان `syncQueue` الموجود.

الخطط التكتيكية تبقى في نظامها الحالي داخل `tactical_plans` وواجهة `/api/plans`. التحليلات تُستخرج من المباريات والأرشيف؛ لذلك لا ننشئ جدول تحليلات منفصلًا.

## ما لن نستخدمه الآن

- لا Cloudflare R2 ولا Bucket ولا تخزين صور أو ملفات.
- لا رفع محادثات TAAMEN AI أو تخزين Transcript في D1. محادثة المستخدم المحلية تبقى محلية، وسلوك استدعاء AI الحالي منفصل ولم يتغير.
- مباريات `PRIVATE` تبقى على الجهاز ولا تُرفع، ويمنعها العميل والخادم.
- السجلات القديمة `legacy` لا تدخل المزامنة.
- لا بريد أو هاتف أو حالة تحقق أو صور شخصية ضمن Payload الملف الشخصي.
- لا إعدادات محلية أو حالة مؤقتة ضمن مزامنة الحساب في هذه المرحلة.

## حالة قاعدة البيانات

تم تأكيد قاعدة Preview باسم `taamen-plans-preview`، وتم تطبيق Migration `0001` الخاصة بـV17 عليها. تضيف V18 ملف Migration جديدًا هو:

`migrations/0002_cloud_sync_engine.sql`

يحتوي `wrangler.jsonc` على ربط `TAAMEN_DB` في بيئة Preview الافتراضية فقط. لا يوجد ربط D1 في `env.production`، ولا تنشئ هذه النسخة قاعدة Production ولا تنشر Worker.

## حدود التشغيل الحالية

حتى مع وجود واجهات `/api/sync/push` و`/api/sync/pull`، فإن `planIdentity` ما زال يرجع `null` عمدًا. لهذا تبقى الواجهات مغلقة وتعيد `401 not_authenticated` إلى أن تنفذ V19 جلسات موثقة، وتُنشئ حسابًا فعليًا في جدول `users`، وتربط الموافقة على المزامنة بالحساب.

وجود `syncQueue` أو عميل API لا يعني أن الموقع بدأ المزامنة تلقائيًا. لم نربط عمليات الحفظ المحلية بالمزامنة بعد، حتى لا تغادر بيانات المستخدم جهازه قبل تنفيذ المصادقة والموافقة الصريحة.

## تشغيل وفحص المشروع على Windows

من PowerShell داخل جذر المشروع:

```powershell
node -v
npm -v
npm ci
npm run typecheck
npm run test:frontend
npm run test:backend
npm run test:worker
npm run qa:final
npm run build:production
npm run preview
```

لا تنشر من هذه المرحلة. يلزم نجاح TypeScript الكامل والبناء الإنتاجي والمعاينة واختبارات المتصفح على جهاز المطور قبل اعتبار الحزمة معتمدة للنشر.
