# حدود الحساب والمزامنة في TAAMEN — V19

## فصل الأنظمة

1. `tactical_plans` وواجهات `/api/plans`: تخزين الخطط التكتيكية المرتبط بحساب موثق، موروث من V17.
2. `sync_records` وواجهات `/api/sync/*`: محرك سجلات V18، لكن V19 يبقيه مغلقًا للمباريات/الملف العام حتى V20.
3. `cloud_sessions` و`account_identities`: هوية المستخدم والجلسات في V19.
4. IndexedDB: المصدر المحلي للمباريات والأرشيف والصور والهاتف والمحادثات والإعدادات.

## مصفوفة الصلاحيات

| مورد | زائر | Local Profile | Cloud Account |
|---|---|---|---|
| الصفحات العامة | قراءة | قراءة | قراءة |
| ملف محلي/صورة/هاتف | لا يوجد ملف | قراءة/كتابة محلي | قراءة/كتابة محلي |
| مكتبة الخطط السحابية | رفض | رفض | وفق الجلسة والملكية |
| أسماء الحساب | غير متاحة | محلية | D1 موثّق |
| البريد | غير متاح | نص محلي غير موثق | بريد موثق، read-only |
| المباريات والأرشيف | لا حفظ ملف | IndexedDB | IndexedDB فقط حتى V20 |
| PRIVATE | محلي عند وجود ملف | محلي | محلي دائمًا |
| AI conversation | لا هوية | محلي | محلي، لا Cloud Chat Storage |
| الجلسات | لا | لا | قراءة/إنهاء ذاتي |

## المزامنة

- حفظ محلي أولًا.
- لا يوجد Background Push أو Pull للمباريات في V19.
- `cloud_sync_consent_at` و`cloud_sync_consent_version` هما سجل تفضيل/موافقة مستقبلية، وليسا مفتاح تشغيل.
- `cloud_sync_enabled` يبقى 0.
- Worker يتحقق من `cloudSyncEnabled` من D1 ولا يقرأه من Request Body.
- V20 يجب أن يعرض السجلات المرشحة قبل النقل، ويستبعد PRIVATE والبيانات الشخصية المحلية والذكاء الاصطناعي والإعدادات.

لا تضف `cloud_sync_enabled=1` يدويًا للاختبار التشغيلي ولا تفعّل المزامنة على الحسابات الحقيقية قبل تنفيذ V20 واختبار جهازين.
