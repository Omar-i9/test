# TAAMEN V19 — Hotfix 02: Guest-first onboarding, language picker, and cloud readiness

## 1. تجربة الدخول الأولى

- الزائر يدخل مباشرة إلى واجهة TAAMEN؛ لا تظهر شاشة التسجيل كحاجز قبل استكشاف الموقع.
- يتم حفظ `taamen-entry-mode=guest` محليًا عند أول دخول بلا ملف أو جلسة سحابية.
- تظهر نافذة ترحيب مرة واحدة فقط: جولة تعريفية أو متابعة كزائر.
- الجولة تمر فعليًا على الرئيسية، مركز المباريات، الملاعب، الملعب التكتيكي، الأرشيف، التحليلات، الإعدادات، ثم TAAMEN AI.
- يضغط المستخدم «التالي» بعد قراءة كل خطوة. يمكنه الرجوع أو إنهاء الجولة.
- النافذة معزولة عن بقية الصفحة أثناء العرض، وتدعم Escape واحتواء التركيز بلوحة المفاتيح.
- لا تنشئ الجولة ملفًا شخصيًا ولا تنقل بيانات إلى السحابة. إنشاء ملف محلي أو حساب سحابي يبقى إجراءً اختياريًا عند الحاجة.

## 2. اللغة

أزيلت رسوم الأعلام من مكوّنات اختيار اللغة في الإعدادات، والدخول، ومعاينة الروابط العامة، والصفحات القانونية، وصفحة الاستحواذ. صار هناك محدد موحّد يعرض اسم اللغة بصيغتها الأصلية؛ اللغة ليست دولة:

| الرمز | الاسم الظاهر | الحالة |
|---|---|---|
| ar | العربية | مكتملة |
| en | English | مكتملة |
| de | Deutsch | BEAT |
| es | Español | BEAT |
| fr | Français | BEAT |
| zh | 中文 | BEAT |
| ja | 日本語 | BEAT |

**تنبيه ترجمة مهم:** العربية والإنجليزية هما مجموعتا الترجمة المكتملتان في هذا الإصدار. اللغات الخمس الجديدة ظاهرة وقابلة للاختيار كمعاينة BEAT، لكن نصوص المنتج ما زالت تستخدم الإنجليزية مؤقتًا. يظهر تنبيه بذلك عند اختيار إحداها. لا يصح اعتبارها ترجمات كاملة قبل تنفيذ ترجمة كل صفحة ومراجعتها لغويًا ووظيفيًا.

يظل اتجاه الواجهة RTL للعربية وLTR لبقية الاختيارات. تبقى لغة محتوى الصفحة الفعلية `en` عند اختيار إحدى لغات BEAT، حتى لا تعلن الصفحة أنها ألمانية بينما تعرض نصًا إنجليزيًا.

## 4. وضع الحسابات والسحابة

هذا التعديل لا يعلن أن Google أو البريد جاهزان تلقائيًا. رد `200 OK` من `/api/auth/config` يثبت وصول الطلب إلى Worker فقط؛ يجب فحص قيم `email` و`google` التي رجعها JSON.

### فحص مزوّدي الحساب على Preview

شغّل المعاينة:

```powershell
npm run preview
```

ومن نافذة PowerShell ثانية في مجلد المشروع:

```powershell
npm run cloud:check
```

الفحص يقرأ `/api/auth/config` و`/api/auth/session` ويطبع هل البريد وGoogle مفعّلان فعلًا. عند ظهور المزوّدين `DISABLED` يلزم استكمال أسرار وإعدادات Preview، ولا يعني ذلك وجود مشكلة في واجهة الموقع.

### شروط تفعيل الحسابات

- بعد نجاح الفحوصات وعزل Worker Preview: تطبيق `0003_verified_cloud_accounts.sql` ثم `0004_account_provider_linking.sql` على D1 Preview فقط.
- إعداد `AUTH_PEPPER`، وقالب EmailJS منفصل للمصادقة (`EMAILJS_AUTH_TEMPLATE_ID`)، و`GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` و`GOOGLE_REDIRECT_URI` عند تفعيل Google.
- إنشاء Worker Preview مستقل باسم خدمة ونطاق منفصلين قبل إضافة الأسرار. اسم Worker الموجود في إعداد الجذر يطابق اسم الإنتاج؛ لا تستخدم `wrangler secret put` على الإعداد الحالي قبل عزل Preview.
- لا تضع الأسرار في `VITE_*` أو داخل ملفات المصدر أو Git.

تحقق أولًا من قائمة ترحيلات Preview:

```powershell
npx wrangler d1 migrations list taamen-plans-preview --remote
```

لا تطبق أي ترحيل إلا بعد التأكد أن قاعدة البيانات هي `taamen-plans-preview` وليست قاعدة الإنتاج، وأن الترحيلين المعلقين هما `0003_verified_cloud_accounts.sql` ثم `0004_account_provider_linking.sql` فقط. لا تعِد 0001 أو 0002. بعد عزل Worker Preview ونجاح فحوصات Windows، طبّقهما بالترتيب على Preview:

```powershell
npx wrangler d1 migrations apply taamen-plans-preview --remote
```

### ما الذي تفعله السحابة في V19؟

- هوية الحساب الموثقة، إدارة الجلسات، وتحديث اسم الحساب.
- مكتبة الخطط التكتيكية السحابية للحساب المؤهل.
- لا تنقل المباريات أو الأرشيف أو الصور أو الهاتف تلقائيًا.
- موافقة مزامنة البيانات في V19 مجرد تفضيل مستقبلي؛ مزامنة المباريات والأرشيف بين الأجهزة تبقى خارج النطاق ومقفلة حتى إصدار V20 بعد معاينة وموافقة مستقلتين.

## 5. تحذير D1 في بناء الإنتاج

لم نضف `d1_databases` إلى `env.production` إطلاقًا؛ قاعدة `taamen-plans-preview` الموجودة على مستوى الجذر مخصصة للـ Preview فقط. لهذا قد يعرض Wrangler تحذيرًا بأن تعريف D1 أعلى الملف غير موروث تلقائيًا إلى الإنتاج. هذا التحذير متوقع هنا: الإنتاج لا يحمل أي `TAAMEN_DB` binding، ولا ننسخ معرّف قاعدة Preview إلى الإنتاج. لا تعالج التحذير بإضافة معرّف Preview إلى إعداد الإنتاج. لم يتم نشر أي شيء إلى Cloudflare تلقائيًا.
